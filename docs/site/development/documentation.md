# 文档维护规范

文档正文直接维护在 `docs/site`，每个页面都是可独立复制的 Markdown。

## 变更同步表

| 代码变更 | 必须同步 |
| --- | --- |
| 新增或修改路由 | API 参考与 curl 示例 |
| 新增 Worker | Agent/Worker 页面、Worker 清单 |
| 修改状态或事件 | 生命周期与事件参考 |
| 新增配置项 | 配置参考和 `.env.example` |
| 新增外部接入 | 能力页、API 页和排查页 |
| 修改默认端口/路径 | 快速开始、配置和排查 |

## 写作规则

- 当前代码行为优先于历史文档；
- 事实、推断和未来方向分开写；
- 不写真实 Token、密码或私密路径；
- 示例必须能复制，必要时说明占位值；
- 实验、外部依赖和兼容接口明确标注；
- 每页给出用途、边界、最小示例和相关页面。

## 发布检查

```powershell
npm run build --prefix C:\\path\\to\\CHARACTOID\docs\site
```

再检查旧名称、错误端口、失效链接和未纳入侧栏的 Markdown。
