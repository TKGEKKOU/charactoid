# 工程实践与面试材料

## 项目解决的问题

许多角色应用只有聊天、TTS 或 Live2D 的独立演示，缺少一条把自然语言目标、安全工具调用、长任务、文件资产和外部接入连起来的工程主线。CHARACTOID 将这些能力统一到角色 Agent 和可恢复 Runtime 中。

## 关键技术选择

### 为什么使用 Supervisor

只有一个对外表达出口，能保持角色人设一致，并防止领域 Worker 绕过证据和权限边界。

### 为什么使用 LangGraph

任务存在分支、工具调用、等待输入、恢复和多轮闭环，显式状态图比单次链式 Prompt 更适合表达这些状态。

### 为什么 RAG 不直接塞进 Prompt

资料需要解析、切分、向量检索、重排、引用和证据不足处理。直接拼接会失去来源、容量控制和质量门。

### 为什么使用 run_id 与 asset_id

`run_id` 把多次工具调用和状态变化组织为一个运行；`asset_id` 让前端和模型不依赖本地绝对路径。

### 控制面与数据面

SQLite 保存角色、状态和元数据；Milvus 保存向量；文件系统保存原文、音频和模型。各自使用适合的数据结构，并允许向量索引重建。

## 失败处理

系统区分未配置、未安装、未启动、运行中、等待输入、失败、取消和完成。错误需要包含阶段与下一步，而不是统一返回“调用失败”。

## 测试策略

- 单元测试：合同、路由、工具分类、状态转换；
- 组件测试：前端状态与交互；
- 集成测试：数据库、向量库、外部服务；
- 端到端测试：创建角色、执行任务、等待确认、返回资产；
- 文档检查：路由覆盖、内部链接和构建。

## 当前限制与演进

- 多个语音组件依赖大型本地模型和 Windows 运行环境；
- 外部平台接入需要独立凭据和稳定网络；
- API 文档目前随源码人工核对，后续可加入 OpenAPI 差异检查；
- 数据库迁移工具尚不是当前重点；
- 更严格的公网认证、租户隔离和远程部署需要额外设计。

## 面试表达建议

用“问题—约束—选择—结果”说明项目：不是罗列用了 FastAPI、Vue 和 LangGraph，而是解释为什么需要 Supervisor、确定性 RAG、任务状态、资产引用和权限边界。
