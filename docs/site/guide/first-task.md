# 完成第一次对话任务

**这页演示如何从一句自然语言开始，观察 CHARACTOID 如何选择能力、创建运行并返回结果。**

你不需要先理解 LangGraph 或 API，就可以先知道一次任务会经历什么，以及什么时候需要你确认。

## 前置条件

- 已按[快速开始](/guide/quickstart)启动服务；
- 已创建至少一个角色；
- 如果测试文件、知识库或语音任务，先准备对应资源。

## 操作步骤

### 1. 发送普通问题

例如：

```text
请用简洁的方式介绍一下你自己。
```

这类请求通常由 Supervisor 直接回答，不会创建复杂的后台任务。

### 2. 发送一个需要能力的目标

例如：

```text
请检查当前知识库是否可以检索，并告诉我缺少什么。
```

或：

```text
请把这个音频准备成可以继续做音色转换的素材。
```

系统会根据请求选择知识、文档、声音或配置相关 Worker。

### 3. 观察运行状态

重点关注：

- `run_id`：本次完整运行的标识；
- Worker 名称：当前由谁处理；
- 状态：排队、运行、等待输入、完成、失败或取消；
- 进度：当前阶段和可读消息；
- 资产：文件结果使用 `asset_id` 或 `file_id` 引用。

### 4. 处理等待确认

涉及写入、安装、发送消息或下一步不明确时，任务会进入 `waiting_input`。阅读提示后选择确认、补充输入或取消，不要重复发送同一条请求。

### 5. 处理完成或失败

完成时，结果和下一步操作会回到同一个对话。失败时先查看阶段、错误信息和资源状态，再选择重试；取消不会被伪装成完成。

## 你应该看到什么

最小闭环应当是：

```text
用户消息
→ Agent 判断
→ Worker（如需要）
→ 状态事件
→ 结果或等待输入
→ 角色回复
```

## 常见错误

| 现象 | 处理 |
| --- | --- |
| 只得到普通回答 | 请求没有形成明确任务目标，补充“检查/执行/导入/生成”等动作和输入。 |
| 任务停在等待输入 | 按卡片提示提供确认或缺少的文件、角色、资源。 |
| 任务失败 | 先看对应 Worker 和资源状态，不要只重复提交。 |
| 没有音频结果 | 确认 TTS/GPT-SoVITS/RVC 运行时和音色资产已就绪。 |
